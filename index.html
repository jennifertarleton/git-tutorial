Git, in plain words

How your practice folder gets to GitHub, and what to do when Git complains.

1. What Git does

Git takes save points of your folder, like save points in a video game.

A save point is called a commit. Each one has a short message, like Week 6 Day 1: four outcomes. If you break something later, you can go back to a save point.

GitHub is a website that keeps a copy of your save points online, so your TA can see your work and you don't lose it.

2. Every class: Save, Commit, Sync

That's it. Three actions, always in this order.

1
Save
Ctrl+S · Mac: Cmd+S

Saves the file. Git can only see saved work.

2
Commit
Source Control → type a message → Commit

Makes a save point on your computer.

3
Sync
Source Control → Sync Changes

Sends your save points up to GitHub, and brings any new ones down.

Saved ≠ committed ≠ on GitHub. If you only save, it's only in the file. If you only commit, it's only on your computer. After Sync, it's on GitHub too.

Step by step in VS Code:

  1. Save your file (Ctrl+S). The white dot ● on the tab goes away.
  2. Click the Source Control icon on the left (it looks like a branch: three dots joined by lines). Your changed files are listed, with an M (modified) or U (new).
  3. Type a message in the box at the top, like Week 6 Day 1: four outcomes.
  4. Click Commit. If VS Code asks "stage all your changes?", click Yes (or Always).
  5. Click Sync Changes. Check on GitHub: your change is there.

Each Monday, the new week's files go into the class copy. They have to travel to your computer in two hops:

  1. Commit your own work first. (This one step prevents most Git errors.)
  2. On GitHub, open your copy of level-2-practice. Click Sync fork → Update branch.
  3. In VS Code, click Sync Changes. The new week's folder appears.
Never click "Discard commits" on GitHub. It deletes your work from your copy. If you see it, see GitHub offers "Discard commits" below.

4. If you see this...

Git almost never loses your work. When it complains, it's stopping so that it doesn't lose work. Find your message below, or type a few words of it:

Nothing matches. Take a screenshot of the whole message and ask.

"Your local changes ... would be overwritten by merge" when you Sync 
error: Your local changes to the following files would be overwritten by merge:
        week-6/day-1/script.js
Please commit your changes or stash them before you merge.

What it means

You changed a file but didn't commit it, and the update changes that file too. Git stops so your work isn't lost.

Do this

  1. Commit your changes (any message).
  2. Click Sync again.
  3. If you now see <<<<<<< in a file, go to Merge conflict.
"Can't push refs to remote. Try running Pull first" when you Push 
Can't push refs to remote. Try running "Pull" first to integrate your changes.
! [rejected]   main -> main (fetch first)

What it means

GitHub has something your computer doesn't have yet (usually because you clicked Sync fork). Git won't send yours up until you have that too.

Do this

  1. Click Sync Changes (not Push). Sync brings things down first, then sends yours up.
  2. In the terminal instead? git pull, then git push.
Merge conflict: <<<<<<< and >>>>>>> in your file after Sync 
CONFLICT (content): Merge conflict in week-6/day-1/script.js

<<<<<<< HEAD
statusText.textContent = "Loading...";       ← yours
=======
statusText.textContent = "Searching...";     ← the update
>>>>>>> ...

What it means

You and the update changed the same line. Git can't guess which one to keep, so it shows you both and lets you choose.

Do this

  1. Above the block, VS Code shows small links. Click one: Accept Current Change keeps yours. Accept Incoming Change keeps the update. Accept Both Changes keeps both.
  2. Check the whole file: no <<<<<<<, ======= or >>>>>>> lines left.
  3. Save, Commit, Sync.
The terminal turned into a strange screen with ~ on every line after git pull 
Merge branch 'main' of https://github.com/you/level-2-practice
# Please enter a commit message to explain why this merge is necessary,
~
~
".git/MERGE_MSG"

What it means

Nothing is broken. Git opened a text editor called Vim so you can write a message. The message is already written for you; you just need to get out.

Do this

  1. Press Esc.
  2. Type :wq (that's colon, w, q).
  3. Press Enter. You're back.
"You have divergent branches" / "Need to specify how to reconcile" git pull in the terminal 
hint: You have divergent branches and need to specify how to reconcile them.
fatal: Need to specify how to reconcile divergent branches.

What it means

Your computer and GitHub both have new save points. Git wants you to choose how to combine them. (VS Code's Sync button chooses for you. The terminal asks.)

Do this

  1. Run this once. You never need it again:
    git config --global pull.rebase false
  2. Run git pull again, then git push.
GitHub's Sync fork says "conflicts" and offers "Discard commits" on GitHub 
This branch has conflicts that must be resolved
[ Open pull request ]   [ Discard 2 commits ]

What it means

The update and your work changed the same file. GitHub can't combine them on the website. Discard would throw away your work to make room. Don't click it.

Do this

  1. Don't click either button. Go to VS Code.
  2. Open the terminal (Terminal → New Terminal), in level-2-practice, and run:
    git pull https://github.com/JenniferT9462/level-2-practice main
  3. That brings the update straight to your computer. If you see <<<<<<<, fix it like a merge conflict. If you see the ~ screen, see the strange screen.
  4. Commit (if it asks), then Sync. Your copy on GitHub is fixed too.
  5. Not sure? Stop and ask. Nothing is lost until someone clicks Discard.
"Please tell me who you are" / "Author identity unknown" when you Commit 
Author identity unknown
*** Please tell me who you are.

What it means

Every save point is signed with a name. This computer hasn't told Git yours yet (new computer, or new setup).

Do this

  1. In the terminal, run these two lines, with your name and the email on your GitHub account:
    git config --global user.name "Your Name"
    git config --global user.email "you@example.com"
  2. Commit again.
"Not a git repository" / Source Control is empty anywhere 
fatal: not a git repository (or any of the parent directories): .git

What it means

The folder you opened isn't connected to Git. Usually it's the wrong folder.

Do this

  1. In VS Code: File → Open Folder → pick level-2-practice itself.
  2. In the terminal: make sure you're inside it (the path ends in level-2-practice).
  3. Did you download a ZIP from GitHub? That copy isn't connected. Ask for help to clone your copy properly.
"Nothing to commit", but I changed the file when you Commit 
nothing to commit, working tree clean

What it means

You didn't save. Git only sees saved work. Look at the file's tab: a white dot ● means not saved.

Do this

  1. Press Ctrl+S (Mac: Cmd+S). Now the file shows up in Source Control.
  2. Commit.
  3. Never again: turn on File → Auto Save.
"I broke it. I want my last save point back." in VS Code

What it means

You can put a file back the way it was at your last commit.

Do this

  1. Source Control → right-click the file → Discard Changes.
  2. ⚠ Everything you typed since your last commit, in that file, is gone. That's why you commit often.
"I pushed my API key to GitHub" anywhere

What it means

Your key is public now. Deleting the file isn't enough: every old save point still has it, and bots search GitHub for keys all day.

Do this

  1. Tell your instructor.
  2. In AI Studio, delete that key and make a new one. A deleted key is useless to anyone who copied it.
  3. Put the new key in config.js only. Check: git status doesn't list config.js.

5. When in doubt

  1. Read the message. It often says the fix: "commit first", "pull first".
  2. Save → Commit → Sync, in that order.
  3. Never click Discard on GitHub.
  4. Still stuck? Screenshot the whole message and ask.

6. Words you'll hear

Commit
A save point, with a message.
Push
Send your save points up to GitHub.
Pull
Bring new save points down from GitHub.
Sync (VS Code)
Pull, then push, in one click.
Fork
Your own copy of someone's project, on GitHub.
Sync fork (GitHub)
Copy new save points from the class copy into your copy.
Merge
Combine two sets of save points into one.
Conflict
Both sides changed the same line, so a person has to choose.
